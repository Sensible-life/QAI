# QAI MVP Scope

작성일: 2026-03-18

## 한 줄 정의

`QAI는 범용 AI QA 툴이 아니라, preview/staging URL의 고위험 퍼널만 검증해 배포 보류 여부를 판단하는 release gate agent다.`

## 이 MVP가 풀 문제

- 로컬에서는 잘 되지만 배포 후 로그인, 폼 제출, 결제가 깨지는 문제
- 전담 QA가 없어 테스트 시나리오를 만들고 유지할 사람이 없는 문제
- 배포 전에 "막아야 하나?"를 빠르게 판단할 수 없는 문제

## 반드시 있어야 하는 기능 5개

1. URL + 계정 정보만으로 시작 가능한 zero-setup 실행
2. 로그인 / 폼 제출 / 체크아웃 전용 퍼널 템플릿
3. 브라우저 액션 로그, 스크린샷, 콘솔, 네트워크 증거 수집
4. 판정 전 재검증 단계로 false positive 감소
5. 배포 가능 / 보류 판단과 수정 포인트를 담은 최종 리포트

## 지금 빼야 하는 기능 5개

1. 범용 자연어 테스트 작성 UX
2. 모든 페이지를 알아서 다 탐색하는 범용 모드
3. 브라우저/OS/디바이스 대규모 매트릭스
4. 엔터프라이즈 권한과 운영 대시보드
5. 사용자가 직접 셀렉터와 테스트 코드를 편집하는 흐름

## Agent인가?

맞다. 다만 `제약된 agent`다.

이 MVP의 agent loop는 아래처럼 제한되어야 한다.

1. Planner: 선택된 퍼널 템플릿으로 실행 계획 생성
2. Runner: 브라우저 조작 및 증거 수집
3. Judge: 실패 여부와 심각도 판정
4. Reporter: 배포 가능 / 보류 리포트 생성

즉 "아무 사이트나 알아서 탐험하는 agent"가 아니라, `미리 정의된 고위험 퍼널을 자동 검증하는 agent`라고 보는 게 맞다.

## 첫 고객

- QA 인력이 없는 초기 SaaS 팀
- 프론트엔드 개발자 1~3명과 PM/창업자가 같이 배포하는 팀
- Vercel/Netlify preview URL을 이미 쓰는 팀
- 로그인, 결제, 신청, 예약 같은 핵심 퍼널이 있는 팀

## 첫 데모 시나리오

가장 좋은 첫 데모는 체크아웃 퍼널이다.

- Preview URL 입력
- 테스트 계정 입력
- 체크아웃 퍼널 선택
- 에이전트 실행
- `배포 보류 권고`, `payment confirm API 500`, `재현 경로`, `증거`를 바로 리포트

이 흐름이 보여주는 가치는 "테스트를 만들었다"가 아니라 "배포 리스크를 바로 알았다"다.

## 제품 메시지

- 나쁜 메시지: AI가 사이트를 돌아다니며 QA해주는 툴
- 좋은 메시지: 배포 전 핵심 퍼널의 기능 장애를 자동 검증하고, 배포를 막아야 할 버그만 근거와 함께 알려주는 release gate

## 구현 우선순위

### 1단계

- 체크아웃 퍼널 1개
- 액션 로그 + 네트워크 + 스크린샷 기반 리포트
- 단일 환경에서만 실행

### 2단계

- 로그인 / 폼 제출 템플릿 추가
- 재검증 및 retry 정책 추가
- Slack / GitHub preview 연동

### 3단계

- 도메인별 퍼널 팩
- release gate 자동화
- 팀별 히스토리와 반복 장애 인사이트
